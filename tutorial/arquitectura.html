Arquitectura profunda

Por qué 12 Activities sueltas y no single-activity, qué declara el Manifest, cómo compila Gradle, qué implica EdgeToEdge.

Gradle / Catalog

gradle/libs.versions.toml:
agp = "9.3.2"
material = "1.10.0"
appcompat = "1.6.1"
constraintlayout = "2.1.4"
activityKtx = "1.8.0" // solo para EdgeToEdge helper
app/build.gradle:
compileSdk = 37, minSdk 27, targetSdk 37
compileOptions Java 11

Version catalog centraliza versiones. foojay-resolver para toolchains. optimization.enable false en release para no ofuscar sandbox.

Theme

values/themes.xml:
Theme.Material3.DayNight.NoActionBar
values-night/themes.xml: hereda igual
colors.xml: primary #6750A4, error #B3261E

NoActionBar evita Toolbar duplicada. Material3 DayNight cambia automáticamente claro/oscuro.

AndroidManifest.xml — técnico

<manifest>
  <uses-permission android:name="android.permission.INTERNET"/>
  <application android:theme="@style/Theme.Sandbox">
    <activity android:name=".MainActivity"
              android:exported="true"
              android:windowSoftInputMode="adjustResize">
      <intent-filter>
        <action android:name="android.intent.action.MAIN"/>
        <category android:name="android.intent.category.LAUNCHER"/>
      </intent-filter>
    </activity>
    <activity android:name=".sandbox.TextInputsActivity"
              android:exported="false"
              android:windowSoftInputMode="adjustResize"/>
    <!-- +10 activities lab, todas exported false -->
  </application>
</manifest>

Solo launcher debe ser exported=true (Android 12+ exige explícito). adjustResize en activities con EditText evita que teclado tape campos. INTERNET solo para WebView; si lo quitas, WebView da net::ERR_INTERNET_DISCONNECTED.

Ciclo de vida y EdgeToEdge

public class MainActivity extends AppCompatActivity {
  protected void onCreate(Bundle savedInstanceState){
    super.onCreate(savedInstanceState);
    EdgeToEdge.enable(this);
    setContentView(R.layout.activity_main);
    ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v,insets)->{
      Insets bars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
      v.setPadding(bars.left, bars.top, bars.right, bars.bottom);
      return insets;
    });
    // findViewById + listeners
  }
}

onCreate es todo

Sin ViewModel ni Fragment: super.onCreate → EdgeToEdge → setContentView → findViewById → setListeners → Prefs precarga. Suficiente para sandbox.

Por qué 12 Activities

Aislamiento didáctico: cada lab con su onCreate. Crashea Lab WebView ≠ crashea Login. En prod usarías Navigation + Fragments, pero aquí verías menos lifecycle explícito.

Trade-off

+ Claridad, + desacoplo, − duplicación de toolbar/theme, − transiciones menos fluidas que NavComponent.

Estructura de carpetas y por qué /tutorial está aislado

Sandbox/ (root)

app/src/main/ módulo Android

java/.../sandbox/*.java

res/layout/*.xml

res/values*/strings.xml

tutorial/ ← HTML estático

index.html, arquitectura.html, auth.html ...

settings.gradle → include ':app' solo app

No vinculada = no compilada

Gradle no conoce tutorial/. No aparece en settings.gradle, no tiene build.gradle. Es web estática con Tailwind CDN (sin npm / sin build). La abres con doble clic.

Constraint vs Linear

Core usa ConstraintLayout (flat, 1 nivel, evita anidación). Labs usan ScrollView>LinearLayout para scroll vertical inmediato sin constraints verbosas.

Java 11

Para que veas findViewById sin synthetics, TextWatcher con 3 métodos, y manejo explícito de null getText()!=null? .... En Kotlin sería by viewBinding + doAfterTextChanged.
