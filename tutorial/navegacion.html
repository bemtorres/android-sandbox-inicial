Cómo cambiar de vista y pasar información

Dos problemas separados: cambiar de pantalla (Intent) y pasar datos (extras, Bundle, Parcelable, SharedPreferences). Aquí cómo se hace en este Sandbox y cómo escalarlo.

Cambiar vista = Intent explícito

Origen conoce Destino.class. Declarado en Manifest.

Pasar dato = putExtra / Bundle / Prefs

Primitivos y Strings por Intent; objetos por Parcelable; sesión por SharedPreferences.

Dentro de la misma Activity

findViewById + setText + listeners. Sin Intent.

1. Cambiar entre vistas (Activity → Activity)

Este proyecto usa Actividad por pantalla (didáctico). En producción migrarías a Navigation Component + Fragments.

Declaración en Manifest — obligatorio

<activity android:name=".MainActivity"
          android:exported="true" > <!-- solo launcher -->
  <intent-filter>
    <action android:name="android.intent.action.MAIN"/>
    <category android:name="android.intent.category.LAUNCHER"/>
  </intent-filter>
</activity>
<activity android:name=".RegisterActivity" android:exported="false"
          android:windowSoftInputMode="adjustResize"/>
<activity android:name=".sandbox.TextInputsActivity" android:exported="false"/>

Android 12+ exige exported explícito. adjustResize evita que teclado oculte EditText.

Disparar navegación desde un botón

// 1) Botón en layout: android:id="@+id/btnLogin"
// 2) En onCreate de MainActivity.java:25
MaterialButton btn = findViewById(R.id.btnLogin);
btn.setOnClickListener(v -> {
  // validar primero...
  Intent i = new Intent(MainActivity.this, RegisterActivity.class);
  startActivity(i); // crea y pone en back stack
});
// En HomeActivity.java:20 — genérico para 7 labs:
private void go(Class<?> cls, String label){
  Toast.makeText(this, getString(R.string.achome_toast_opening, label), SHORT).show();
  startActivity(new Intent(this, cls));
}
findViewById(R.id.cardInputs).setOnClickListener(v -> go(TextInputsActivity.class, "TextInputs"));

new Intent(context, Destino.class) = Intent explícito (sabes a dónde vas). Implícito sería ACTION_VIEW para abrir browser.

Back stack

Cada startActivity apila. Botón sistema ← hace pop. finish() cierra actual sin ir a nueva. finishAffinity() cierra toda la tarea.

findViewById(R.id.tvGoLogin).setOnClickListener(v -> finish());

Edge: WebView

@Override public void onBackPressed(){
  if(webView.canGoBack()) webView.goBack(); // historial interno
  else super.onBackPressed(); // pop Activity
}

Flags útiles

i.addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP);
i.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK); // logout

Sandbox no los usa (flujo lineal), pero en login real limpiarías stack al ir a Home.

2. Pasar información entre vistas

4 niveles: Intent extras → Bundle → Parcelable → SharedPreferences/ViewModel. En Sandbox usamos extras simples + Prefs.

Caso real del Sandbox — flujo Login → Registro → Intro

PASO 1: MainActivity → RegisterActivity

// MainActivity.java:50
String email = etEmail.getText().toString().trim();
Intent i = new Intent(this, RegisterActivity.class);
i.putExtra("email", email); // key "email"
startActivity(i);

PASO 2: RegisterActivity lee + guarda

// RegisterActivity.java:40
String incoming = getIntent().getStringExtra("email");
if(incoming==null) incoming = Prefs.getUser(this); // fallback Prefs
etEmail.setText(incoming);
// Al validar OK:
Prefs.saveUser(this, email);
Intent i = new Intent(this, IntroActivity.class);
i.putExtra("name", name);
i.putExtra("email", email);
startActivity(i);

PASO 3: IntroActivity lee y muestra

// IntroActivity.java:17
String name = getIntent().getStringExtra("name");
String email = getIntent().getStringExtra("email");
if(email==null) email = Prefs.getUser(this);
if(name==null || name.isEmpty()) name = email;
tvUser.setText(getString(R.string.common_msg_hello, name));
// ¡Hola, Javier!

Patrón: putExtra con key string literal → getStringExtra + null-check → fallback a Prefs. Placeholder %1$s en common_msg_hello se resuelve con getString(…, name).

2.1 Intent extras — tipos y Bundle

// Primitivos y Strings
i.putExtra("age", 27); // int
i.putExtra("price", 9.99); // double
i.putExtra("isPro", true);
i.putExtra("email", "a@b.com");

// En destino:
int age = getIntent().getIntExtra("age", -1);
double price = getIntent().getDoubleExtra("price", 0.0);
boolean isPro = getIntent().getBooleanExtra("isPro", false);
String email = getIntent().getStringExtra("email"); // nullable

// Bundle explícito (misma idea, más orden):
Bundle b = new Bundle();
b.putString("name", name);
b.putString("email", email);
i.putExtras(b);
// getIntent().getExtras() → Bundle

Keys por convención EXTRA_*_KEY constantes. Sandbox usa literales simples ("email","name") para claridad.

2.2 Objetos: Parcelable (no usado en Sandbox, pero patrón)

// Model
public class User implements Parcelable {
  String name, email;
  // ... Parcelable impl o @Parcelize en Kotlin
}
// Enviar:
i.putExtra("user", user); // Parcelable
// Recibir:
User u = getIntent().getParcelableExtra("user", User.class); // API 33+
// o
User u = getIntent().getParcelableExtra("user");

¡Cuidado!

TransactionTooLargeException si pasas bitmaps grandes por Intent (>1MB Binder). Usa archivo, URI o ViewModel.

2.3 SharedPreferences — sesión fake (Prefs.java)

// utils/Prefs.java
private static final String NAME = "sandbox_prefs";
private static final String KEY_USER = "user_email";
public static void saveUser(Context c, String email){
  c.getSharedPreferences(NAME, MODE_PRIVATE).edit().putString(KEY_USER, email).apply();
}
public static String getUser(Context c){
  return c.getSharedPreferences(NAME, MODE_PRIVATE).getString(KEY_USER, "");
}

Persistente entre Activities y reinicios. apply() async vs commit() sync. Para sesión real usarías EncryptedSharedPreferences o DataStore.

Errores comunes y checklist

❌ Errores típicos

  • getStringExtra devuelve null si key no existe → siempre null-check o default.
  • Typo en key: putExtra("emial",…) vs getStringExtra("email") → define public static final String EXTRA_EMAIL="email".
  • Pasar objeto grande (>1MB) por Intent → TransactionTooLargeException.
  • Olvidar exported o intent-filter en Manifest → app no aparece en launcher.
  • Usar getIntent() en sin guardar → se pierde tras onNewIntent en singleTop.

✅ Checklist antes de navegar

  • ¿Activity declarada en AndroidManifest.xml con exported?
  • ¿Keys de extras centralizadas y con default?
  • ¿trim() en Strings de EditText?
  • ¿Fallback a Prefs si extra es null?
  • ¿Placeholder %1$s coincide en es/en/pt?
  • ¿Probado cambio de idioma y rotación (config change no pierde dato)?
