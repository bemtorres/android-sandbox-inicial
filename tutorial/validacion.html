Validación — arquitectura en 3 capas

Separación: ValidationUtils (lógica pura) → Activity (orquesta UI) → TextWatcher (feedback en vivo). Ninguna Activity duplica regex.

ValidationUtils.java:11

utils/ValidationUtils.java

private static final Pattern PHONE = Pattern.compile("^\\+?[0-9 ]{9,15}$");
private static final Pattern POSTAL = Pattern.compile("^\\d{5}$");
private static final Pattern PIN = Pattern.compile("^\\d{4,6}$");

isRequired(s) // s!=null && !trim.empty
isEmail(s) // Patterns.EMAIL_ADDRESS.matcher
isPassword(s) // length >= 6
isNumericPassword(s) // PIN.matcher
isPhone(s) // PHONE.matcher && digits 9-15
isPostalCode(s) // POSTAL.matcher
isNotFuture(millis) // millis <= System.currentTimeMillis()

Testeable unitario: sin Context, sin UI.

Capa 2 — UI en Activity

Ejemplo TextInputsActivity

boolean ok = true;
if(!isRequired(phone)){
  tilPhone.setError(getString(common_err_required)); ok=false;
} else if(!isPhone(phone)){
  tilPhone.setError(getString(common_err_phone)); ok=false;
} else tilPhone.setError(null); // limpia
// ... repetir por campo
if(!ok){
  Toast.makeText(this, common_msg_correct_errors, SHORT).show();
  Log.e(TAG, "Validación fallida");
  return;
}
Toast.makeText(this, common_toast_validation_ok, SHORT).show();

Orden: required primero → formato después → limpia error si ok.

Capa 3 — TextWatcher (opcional)

etEmail.addTextChangedListener(new SimpleWatcher(){
  void afterTextChanged(Editable s){
    if(ValidationUtils.isEmail(s.toString()))
      tilEmail.setError(null); // no valida, solo limpia
  }
});

No bloquea; solo quita rojo si ya es válido. Usado en Registro (email, postal) para no spamear Toast mientras escribe.

Anti-patrones evitados

  • No validar en onTextChanged con Toast (spam).
  • No duplicar regex en cada Activity.
  • No usar android:digits para validar; inputType no sustituye regex.
