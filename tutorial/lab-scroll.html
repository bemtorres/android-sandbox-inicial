Lab 9 — Lista simple con ScrollView

Cuando la lista es corta (<20) y no necesitas reciclaje. Todo inflado a la vez con ScrollView > LinearLayout.

Layout — ScrollView + LinearLayout

<LinearLayout orientation="vertical">
  <MaterialCardView> // header acscro_info_desc </CardView>
  <ScrollView layout_weight="1">
    <LinearLayout android:id="@+id/container"
                  orientation="vertical"/>
  </ScrollView>
</LinearLayout>

container es donde se hace addView en bucle.

Inflado dinámico en bucle

LinearLayout container = findViewById(R.id.container);
LayoutInflater inflater = LayoutInflater.from(this);
for(String[] row : data){
  View item = inflater.inflate(R.layout.item_contact, container, false);
  ((TextView)item.findViewById(R.id.tvName)).setText(row[0]);
  ((TextView)item.findViewById(R.id.tvEmail)).setText(row[1]);
  ((TextView)item.findViewById(R.id.tvPhone)).setText(row[2]);
  item.setOnClickListener(v -> {
    Toast.makeText(this, getString(R.string.acscro_toast, row[0]), SHORT).show();
  });
  container.addView(item);
}

10 inflates → 10 addView. Sin Adapter, sin ViewHolder. Simple pero no recicla.

Cuándo usar ScrollView vs RecyclerView

ScrollView ✅

Lista corta, estática, <20 items, sin scroll anidado, prototipo rápido.

RecyclerView ✅

Lista larga/dinámica, reciclaje, animaciones, diff, paginación.

ScrollView con 100 contactos = 100 views en memoria → lag. Recycler recicla ~7-10 views visibles.

Cómo se desarrolló

  1. Crea activity_simple_scroll_list.xml con header card + ScrollView container.
  2. Reusa item_contact.xml (mismo componente que Recycler: | foto | nombre correo teléfono |).
  3. En SimpleScrollListActivity.java define String[][] data 10 filas.
  4. Loop inflate → findViewById → setText → setOnClickListener → addView + log SANDBOX_SCROLL.
